    CI/CD with Jenkins, step by step

    CI (continuous integration) builds and tests every commit. CD (continuous delivery) ships the tested build to a server. Jenkins is the tool that runs this chain for you. Follow the 8 steps below to build it yourself.

    Developer›GitHub›Webhook›Jenkins EC2›Build + Test›Docker Hub›App EC2
    1

    Launch the Jenkins server

    Create an Ubuntu EC2 (t3.medium is comfortable). In its security group allow port 22 from your IP only, and port 8080 for the Jenkins web page. Then install Java and Jenkins by following the official Linux guide at jenkins.io, and start it.

    sudo systemctl enable --now jenkins
sudo cat /var/lib/jenkins/secrets/initialAdminPassword
# open http://SERVER_IP:8080 and paste that password
    2

    Install Docker and give Jenkins access

    Jenkins runs docker commands, so its user must be in the docker group. Restart Jenkins after this change.

    sudo apt install -y docker.io
sudo usermod -aG docker jenkins
sudo systemctl restart jenkins
    3

    Install the plugins

    Manage Jenkins → Plugins → Available. Install these:

    • Git and GitHub to pull code and receive webhooks
    • Pipeline to run a Jenkinsfile
    • Docker Pipeline for docker steps
    • SSH Agent to deploy over SSH
    4

    Add credentials

    Manage Jenkins → Credentials → Global → Add. Never write passwords inside the Jenkinsfile.

    • dockerhub-creds: type Username with password. Use a Docker Hub access token as the password.
    • ec2-ssh-key: type SSH Username with private key. Paste the key of the app server.

    The ID you type here must match the ID used in the Jenkinsfile exactly.

    5

    Write the Jenkinsfile

    Save this file named Jenkinsfile in the root of your repo. Each stage is one step of the pipeline: checkout, build and test, image build, push, deploy.

    pipeline {
  agent any
  environment {
    IMAGE = 'myuser/app'
    TAG   = "${BUILD_NUMBER}"
  }
  stages {
    stage('Checkout') {
      steps { git branch: 'main', url: 'https://github.com/myuser/app.git' }
    }
    stage('Build and Test') {
      steps { sh 'npm ci && npm test && npm run build' }
    }
    stage('Docker Build') {
      steps { sh 'docker build -t $IMAGE:$TAG .' }
    }
    stage('Push') {
      steps {
        withCredentials([usernamePassword(credentialsId: 'dockerhub-creds',
            usernameVariable: 'U', passwordVariable: 'P')]) {
          sh 'echo $P | docker login -u $U --password-stdin'
          sh 'docker push $IMAGE:$TAG'
        }
      }
    }
    stage('Deploy') {
      steps {
        sshagent(['ec2-ssh-key']) {
          sh '''ssh -o StrictHostKeyChecking=no ubuntu@10.0.1.10 "
            docker pull $IMAGE:$TAG &&
            docker rm -f app || true
            docker run -d --name app -p 80:80 $IMAGE:$TAG"'''
        }
      }
    }
  }
  post {
    success { echo 'Deployed' }
    failure { echo 'Failed, check the console output' }
  }
}

    For a private EC2 with no SSH, replace the deploy step with AWS SSM:

    aws ssm send-command --instance-ids i-0abc --document-name AWS-RunShellScript \
  --parameters 'commands=["docker pull myuser/app:1.0","docker rm -f app || true","docker run -d --name app -p 8080:8080 myuser/app:1.0"]'
    6

    Create the pipeline job

    • Dashboard → New Item → name it, choose Pipeline
    • Pipeline definition: Pipeline script from SCM
    • SCM: Git, paste your repo URL, branch */main
    • Script Path: Jenkinsfile
    • Tick GitHub hook trigger for GITScm polling, then Save
    7

    Connect GitHub with a webhook

    In your GitHub repo: Settings → Webhooks → Add webhook.

    Payload URL:  http://SERVER_IP:8080/github-webhook/
Content type: application/json
Event:        Just the push event

    Now every push starts the pipeline automatically.

    8

    Run it and check the result

    Push a small change. Open the job, click the build number, then Console Output to watch each stage. When it ends with SUCCESS, open http://APP_SERVER_IP and you should see the new version.

    Common errors and fixes

    docker: permission deniedJenkins user is not in the docker group. Run step 2 and restart Jenkins.
    Webhook does not start the buildPort 8080 is blocked in the security group, or the URL misses the trailing slash. Check Recent Deliveries in GitHub.
    Host key verification failedAdd -o StrictHostKeyChecking=no, or add the server to known_hosts.
    Credentials not foundThe credentialsId in the Jenkinsfile does not match the ID in Jenkins.
    No space left on deviceOld images fill the disk. Run docker system prune -f and clean old workspaces.
    Good habits: keep the Jenkinsfile in Git, tag images with the build number, use a Docker Hub access token not your password, restrict port 8080 where you can, and back up /var/lib/jenkins.
    Build one project per stage and push it to GitHub. A visible repo beats a long list of certificates.
